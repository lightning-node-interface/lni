# @sunnyln/lni-lexe-nodejs

Lexe-only native Node.js bindings for LNI. Includes Lexe Connect, wallet info,
receiving capability checks, exclusive Bitcoin addresses, address synchronization,
Lightning invoices, on-chain payments, and invoice monitoring.

This package exports only Lexe. Spark and Arkade are excluded; unused core
provider code is removed by the optimized release linker. The Rust wallet implementation and JavaScript helpers are shared with
`bindings/lni_nodejs`.

```js
const { LexeNode, LexeConnect } = require('@sunnyln/lni-lexe-nodejs')
const { withLexeNode } = require('@sunnyln/lni-lexe-nodejs/lexe')

const capabilities = await withLexeNode(credentials, (node) => node.getReceivingCapabilities())
```

For ES modules, use a default import for the CommonJS root:

```js
import lni from '@sunnyln/lni-lexe-nodejs'
import { withLexeNode } from '@sunnyln/lni-lexe-nodejs/lexe'
const { LexeNode, LexeConnect } = lni
```

Keep credentials and Connect seeds on the server. See [LEXE.md](LEXE.md) for
scopes, session storage, expiry, cancellation, and the `checkAddress` calls
required after detecting payments to exclusive addresses.

## Platform binary

The supported native target is Linux x64 with glibc, built on Ubuntu CI. The root
package contains JavaScript and generated TypeScript declarations. Its exact-version
optional dependency, `@sunnyln/lni-lexe-nodejs-linux-x64-gnu`, supplies the addon.
Do not omit optional dependencies. Linux CI builds use glibc 2.28.

Other operating systems, ARM64, and musl are not release targets. This package
requires a Node.js server runtime and cannot load in a browser or Edge runtime.
Externalize the package in server bundlers and preserve its native dependency.

`/lexe` is lazy: importing the helpers does not load the native addon. The root
entry point loads the addon immediately. Runtime JavaScript preserves Node 10.16
compatibility; development and CI tools use Node.js 22.

## Build and test locally

Run these commands from `bindings/nodejs-lexe` with a compatible Rust toolchain
and C/C++ compiler installed:

```sh
corepack yarn install --immutable
corepack yarn check:native-deps
corepack yarn build
corepack yarn typecheck
corepack yarn test
corepack yarn test:release
corepack yarn pack:dry-run
corepack yarn test:install
```

The package uses the repository's pinned Yarn 4.6.0 binary. `build` uses the
workspace's `lexe-nodejs-release` Cargo profile: size optimization, full LTO,
one codegen unit, no debug info, and stripped symbols. Other bindings keep their
own build profiles. `build:debug` makes an unoptimized local addon.

LNI's core providers and dependencies remain unconditional. This binding exports
only Lexe's Node classes and selects the public TypeScript types in `index.d.ts`.
The generated declarations also contain internal core types. Release linking
removes unused code from the final addon. Spark remains an opt-out feature so
experimental SDK code stays out of native Node packages.

`native.js` and `generated/index.d.ts` are generated by napi-rs. Shared runtime files and contracts,
helper TypeScript, helper build output, and Lexe documentation are copied from
`bindings/lni_nodejs` by `sync:runtime`. The public `index.d.ts` barrel is maintained by this package. Edit the shared
originals for runtime changes, then rebuild
and commit the regenerated copies. Package checks reject drift between copies
and their source, and compile the helper against this package's own generated
Lexe declarations. Offline JavaScript tests also run against the copied runtime.
Shared packaging tools are called through `scripts/run.cjs`.

`test:lexe-monitor` builds a separate debug library with synthetic monitor hooks
and runs the native lifecycle tests. Those hooks are never enabled in release
builds and do not overwrite the packaged release addon.

## Packed consumer installation

```sh
# Linux x64 is the supported native target.
corepack yarn pack:platforms ./dist linux-x64-gnu
corepack yarn test:install ./dist
```

The first command writes the root and platform tarballs plus an integrity
manifest to `dist/`. It requires the Linux x64 binary and fails if it is missing. `test:install` creates a clean consumer with an
isolated offline npm cache and installs both tarballs. It verifies real native
loading from the platform package, CommonJS and ESM imports, generated types,
Lexe Connect session restoration, receiving APIs, and the absence of other
providers. It sends no wallet requests and does not publish anything.

To install the Linux x64 tarballs in another local project, copy them there and
run:

```sh
npm install ./sunnyln-lni-lexe-nodejs-0.1.0.tgz ./sunnyln-lni-lexe-nodejs-linux-x64-gnu-0.1.0.tgz
```

After publication, consumers can install `@sunnyln/lni-lexe-nodejs` directly.
They do not need Rust or build tools.

## Release workflow

[build-lexe-nodejs.yml](../../.github/workflows/build-lexe-nodejs.yml) builds on
Ubuntu x64, tests packed consumer installs, collects the native binary
with napi-rs, and packs the complete release set. Branch and pull-request runs,
and manual runs, only build and upload artifacts.

Only a pushed tag exactly matching `lni-lexe-nodejs-v<package.json version>` can
publish. The workflow validates the package set, tag, and tarball integrity,
publishes platform tarballs first and the root tarball last, and attaches the
packages to a GitHub release. Beta releases use npm's `beta` tag, other
prereleases use `next`, and stable releases use `latest`. Publishing requires
the repository's `NPM_TOKEN` secret.

The first release is prepared as `0.1.0-beta.1`. Its release tag will be
`lni-lexe-nodejs-v0.1.0-beta.1`. Pushing that tag publishes the package; do not
push it until npm authentication is configured and the release is approved.

To change the npm version, edit `package.json`, run `corepack yarn
version:platforms`, then run `corepack yarn install` and commit the updated
platform metadata and lockfile. Do not invoke `napi prepublish`: its lifecycle
can publish other packages as a side effect.
